# 客服话术质量标注说明文档 v1.0

> 版本：v1.0 | 时间：2026-03-31
> 用途：人工标注多轮客服对话质量，为 cs-judge 模型提供 ground truth
> 评测对象：cs-data-factory 生产的多轮客服对话，逐轮评估**当前轮客服回复**的质量

---

## 一、任务说明

### 1.1 你需要做什么

你会拿到若干条**多轮客服对话**，每条数据包含：
- **历史消息**：当前轮之前的完整对话（含用户说的话和客服之前的回复）
- **话术回复**：当前轮客服的回复（**这是你要评估的内容**）

你的任务是：**阅读历史消息，理解上下文，然后对"话术回复"进行打分。**

### 1.2 打分逻辑

每条话术回复需要：

1. **识别本轮涉及哪些服务动作**（见第二章）
2. **对涉及的维度逐一打分**（见第三章）
3. **对"不涉及"的维度，直接填"不涉及"，不打分**

### 1.3 重要原则

- **以历史消息为上下文**：历史对话中已经说清楚的信息，本轮无需重复也视为合格
- **只评估"话术回复"**，不是评价整个对话
- **以用户实际感受为标准**：站在用户角度，这条回复有没有帮到你、说清楚了吗
- **有疑问优先看示例**，示例是最直观的判断依据

### 1.4 打分表格格式

每条数据填写如下表格：

| 维度 | 分数 | 备注（可选） |
|---|---|---|
| A1. 关键信息呈现 | 不涉及 / 0 / 1 / 2 | |
| A2. 高效厘清 | 不涉及 / 0 / 1 / 2 | |
| B1. 外呼信息 | 不涉及 / 0 / 1 | |
| B2. 外呼后备选方案 | 不涉及 / 0 / 1 | |
| B3. 安抚等待 | 不涉及 / 0 / 1 | |
| C1. 背景信息总结 | 不涉及 / 0 / 1 | |
| C2. 精准提问 | 不涉及 / 0 / 1 | |
| D1. 凭证信息 | 不涉及 / 0 / 1 | |
| D2. 凭证补充说明 | 不涉及 / 0 / 1 | |
| E1. 背景信息补充 | 不涉及 / 0 / 1 / 2 | |
| E2. 方案呈现 | 不涉及 / 0 / 1 / 2 | |
| E3. 安抚劝说 | 不涉及 / 0 / 1 | |
| F1. 服务结论确认 | 不涉及 / 0 / 1 | |
| F2. 礼貌道别/祝福 | 不涉及 / 0 / 1 / 2 | |
| G1. 共情质量 | 不涉及 / 0 / 1 / 2 | |

## 二、服务动作识别

打分前，先判断本轮话术属于哪种服务动作。**一轮可以同时属于多种动作。**

| 动作标签 | 定义 | 典型特征 |
|---|---|---|
| **open_clarify** | 开场厘清 | 提炼用户背景信息 + 询问用户诉求 |
| **info_outbound** | 外呼确认 | 告知用户去联系第三方（商家/骑手等）核实信息 |
| **info_direct_ask** | 直接询问用户 | 向用户索取信息（"您现在收到餐了吗"） |
| **info_evidence** | 索要凭证 | 要求用户提供截图、视频等证据材料 |
| **solution_propose** | 方案协商 | 给出解决方案（退款、补偿、申诉通过等）|
| **closing** | 结束语 | 对话即将结束，总结+礼貌道别 |
| **empathy** | 共情回复 | 用户有负面情绪，客服进行情绪安抚 |

## 三、各维度打分规则

---

### A. open_clarify（开场 & 厘清）

#### A1. 关键信息呈现

**评估重点：** 客服有没有准确、精炼地说出与用户问题相关的关键背景？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮没有提炼背景信息的内容 |
| **2分** | 完整、准确、精炼地提炼了与用户诉求有关的重要信息 |
| **1分** | 提炼了信息，但包含冗余/无关内容 |
| **0分** | 没有提炼信息，或提炼了错误信息 |

**✅ 2分示例：**
> 话术：「看到您这边申请了一个放心吃理赔被驳回了，是想咨询相关原因吗？」
> 解析：准确提炼了"申请理赔被驳回"这一核心背景，简洁无冗余。

**⚠️ 1分示例：**
> 话术：「看到您有一个超时违规和一个提前点送达违规，然后运单其他状态都是正常的，这边看到没有问题，您是要申诉违规对吧？」
> 解析："其他状态都是正常的，这边看到没有问题"是冗余信息，用户不需要知道这些。

**❌ 0分示例：**
> 话术：「您好！很高兴为您服务，有什么问题可以帮您？」
> 解析：没有任何背景信息提炼，空话开场。

---

#### A2. 高效厘清

**评估重点：** 客服询问诉求的方式是否高效？有没有根据上下文预判诉求？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮没有向用户询问诉求 |
| **2分** | 根据背景预判了诉求，用精准的封闭式提问确认（"您是想申诉这个违规是吗？"）|
| **1分** | 笼统地问"有什么问题"，或提问中有啰嗦/重复/语病 |
| **0分** | 严重语病导致意思不清，或没有询问直接给出结论 |

**✅ 2分示例：**
> 历史：订单显示骑手上报联系不到用户，发起二次配送，配送超时
> 话术：「看到这个订单是上报联系不到用户，发起二次配送超时了，您是想申诉这个超时违规是吗？」
> 解析：根据订单信息预判"申诉超时违规"，精准确认，不让用户重新说一遍。

**⚠️ 1分示例：**
> 话术：「您是想申诉超时违规还是想申诉提前点送达违规？还是有其他别的问题？」
> 解析：最后加"还是有其他别的问题"是多余的，显得不够专业。

**❌ 0分示例：**
> 话术：「您继续等着系统通知就行，辛苦耐心等待哈。」
> 解析：没有询问诉求，直接给出结论，可能完全猜错了用户想要什么。

---

### B. info_outbound（外呼确认）

#### B1. 外呼信息

**评估重点：** 外呼前有没有说清楚"联系谁"和"核实什么"？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮没有告知用户要外呼 |
| **1分** | 同时说清楚了"联系谁"和"核实什么内容" |
| **0分** | 缺少其中任何一项 |

> 注意：历史消息中前几轮已经说明过外呼对象和目的，本轮直接说"我现在帮您联系"也算 1 分。

**✅ 1分示例：**
> 话术：「我现在帮您联系骑手，核实一下餐品是否已经送达您的收餐地址，您听到音乐不要挂断哈。」
> 解析：说了"联系骑手"（联系谁）+ "核实餐品是否送达"（核实什么），完整。

**❌ 0分示例A（缺少核实内容）：**
> 话术：「我去帮您联系骑手核实下，您听到音乐后不要挂机。」
> 解析：没说核实什么，用户不知道结果会是什么。

**❌ 0分示例B（缺少外呼对象）：**
> 话术：「我去问问什么情况，您听到音乐后不要挂机。」
> 解析：没说联系谁，也没说核实什么。

---

#### B2. 外呼后备选方案（加分项）

**评估重点：** 有没有告知用户"如果结果是正向的，接下来会怎么做"？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮没有外呼内容，或是外呼后回来汇报（非外呼前告知）|
| **1分** | 给出了正向的"如果…，我就帮您…"后续路径 |
| **0分** | 没有给出后续路径，或给出负向预测 |

**✅ 1分示例：**
> 话术：「我联系一下商家，如果商家同意，我马上给您操作退款。」

**❌ 0分示例（负向预测）：**
> 话术：「如果用户不同意的话，咱们这边就不能给您退款了。」
> 解析：先给负向结果，加重用户焦虑。

---

#### B3. 安抚等待

**评估重点：** 有没有给用户明确的等待时间范围，并告知不要挂机？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮没有外呼内容 |
| **1分** | 给出具体到分钟范围的等待时长（如"1-3分钟"）+ 告知不要挂机 |
| **0分** | 没有告知等待时长，或只说"稍等"没有具体时间 |

**✅ 1分示例：**
> 话术：「请您稍等我一到两分钟，听到音乐不要挂断哈。」

**❌ 0分示例：**
> 话术：「我这边帮您联系骑手，您稍等我下。」
> 解析："稍等我下"没有时间范围。

---

### C. info_direct_ask（直接询问用户）

#### C1. 背景信息总结

**评估重点：** 问问题之前，有没有先解释"为什么问这个"？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮没有向用户提问 |
| **1分** | 提问前解释了询问原因，让用户明白问题和他的诉求有关 |
| **0分** | 没有任何背景铺垫，直接问问题 |

> 注意：历史消息中已经说明过询问背景，本轮直接问也算 1 分。

**✅ 1分示例：**
> 话术：「后台查看到订单是商家自配送的，所以您这边看不到骑手信息，您这边愿意继续等待吗？」
> 解析：先解释了"为什么看不到骑手信息"，再问用户的意向。

**❌ 0分示例：**
> 话术：「您现在收到餐了吗？」
> 解析：直接问，用户不知道为什么要回答这个。

---

#### C2. 精准提问

**评估重点：** 问题本身是否清晰直接？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮没有向用户提问 |
| **1分** | 问题清晰，用户能直接理解并回答 |
| **0分** | 问题含糊拐弯抹角，或表述不严谨容易引起误解 |

**✅ 1分示例：**
> 话术：「了解，看到您给用户打电话没人接听，那您现在是把餐放到用户门口了吗？」
> 解析：问题直接，用户只需回答是/否。

**❌ 0分示例：**
> 话术：「那您然后呢？怎么处理的餐品呀？」
> 解析：含糊，用户不知道从哪里开始说。

---

### D. info_evidence（索要凭证）

#### D1. 凭证信息

**评估重点：** 有没有说清楚"提供什么凭证"和"怎么上传"？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮没有要求用户提供凭证 |
| **1分** | 说清楚了"提供什么凭证"和"怎么上传"（**电话客服**两者缺一不可；**在线客服**只需说清楚凭证内容）|
| **0分** | 缺少凭证内容描述，或（电话客服）缺少上传路径 |

**✅ 1分示例（电话客服）：**
> 话术：「稍后我给您发一个短信，您把骑手拒绝取餐的沟通截图上传到对应的链接里就可以。」

**✅ 1分示例（在线客服）：**
> 话术：「辛苦您提供一下骑手偷餐的凭证，图片或者视频截图都可以。」

**❌ 0分示例：**
> 话术：「您看看这边可以提供一下凭证吗？」
> 解析：没说要什么凭证。

---

#### D2. 凭证补充说明（加分项）

**评估重点：** 有没有告知用户"凭证核实后会怎么处理"？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮没有索要凭证 |
| **1分** | 告知了凭证核实后的正向处理路径，或解释了为什么需要凭证 |
| **0分** | 没有给后续预期，或给出负向结果 |

**✅ 1分示例：**
> 话术：「如果确认骑手存在偷餐行为，这边会帮您做退款处理，同时也会对骑手行为进行处罚。」

**❌ 0分示例：**
> 话术：「如果不是平台骑手行为的话，就不能给您操作退款了。」

---

### E. solution_propose（方案协商）

#### E1. 背景信息补充（加分项）

**评估重点：** 给方案之前，有没有简短解释背景让用户明白"为什么是这个方案"？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮没有背景补充（背景上文已说清楚），直接给方案 |
| **2分** | 用针对本案的专业语言，清楚说明了背景或核实结果 |
| **1分** | 给了背景，但是通用套话，没有针对这个具体案子 |
| **0分** | 没有说背景，或与历史消息中已说过的内容高度重复 |

> 注意：历史消息中已经充分解释过背景，本轮直接给方案，此维度填"不涉及"。

**✅ 2分示例：**
> 话术：「这边联系骑手核实了，骑手表示按照您的收餐地址已经给您送达，骑手也已经离开了，确实没有办法再修改地址，建议您去收餐地自取一下呢。」
> 解析：针对本订单的具体核实结果，不是套话。

**⚠️ 1分示例：**
> 话术：「根据平台要求，退款前需要先与商家协商呢，我这边还是需要联系一下商家才能给您答复。」
> 解析：通用规则，没有针对这个订单的具体情况。

**❌ 0分示例：**
> 话术：「帮您申请到了一份五元的余额补偿，您看可以吗？」
> 解析：方案从天而降，用户不知道为什么，也不知道基于什么做出了这个决定。

---

#### E2. 方案呈现

**评估重点：** 方案是否清晰具体，用户知道接下来会发生什么？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮没有给出方案 |
| **2分** | 方案清晰、具体、可执行，用户知道接下来会发生什么 |
| **1分** | 方案方向对，但不够清晰，用户可能还有疑问 |
| **0分** | 方案与用户诉求无关，或只是陈述问题而非给方案 |

**✅ 2分示例：**
> 话术：「这边给您把红包换成五元余额，余额是可以提现到银行卡的，您看可以吗？」
> 解析：方案清晰（换成余额），消除了疑虑（可提现），并征询意见。

**⚠️ 1分示例：**
> 话术：「明白，您这边吃到异物所以申请了退款，但是商家拒绝了。」
> 解析：陈述问题，不是方案，用户仍不知道怎么解决。

**❌ 0分示例：**
> 话术：「您申请一下客服介入吧。」
> 解析：把问题踢回给用户，不是方案。

---

#### E3. 安抚劝说

**评估重点：** 给出方案后，有没有做情感引导帮用户接受？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮没有方案，或方案对用户完全有利不需要劝说 |
| **1分** | 有情感引导（解释方案为何适合、以商议姿态询问、提供替代方案）|
| **0分** | 没有任何劝说，直接问"可以吗"；或劝说话术明显不当 |

**✅ 1分示例：**
> 话术：「虽然这个钱不多，但也是咱平台这边一点心意，希望您可以收下，点杯奶茶消消气，您看可以吗？」

**❌ 0分示例（无劝说）：**
> 话术：「我这边给您申请全额退款25.8元，稍后退到您的账户余额，您看可以吗？」
> 解析：事务性告知，缺少情感温度（注：若方案完全满足用户诉求，此维度可填"不涉及"）

**❌ 0分示例（话术不当）：**
> 话术：「建议您亲自配送，就像您送自己的孩子上学一样……」
> 解析：类比失当，用户会反感。

---

### F. closing（结束语）

#### F1. 服务结论确认

**评估重点：** 结束前有没有承接上文，哪怕一句"好的"？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮不是结束语 |
| **1分** | 简单总结服务结论，或用"好的""嗯嗯"承接上文 |
| **0分** | 没有任何承接，直接说再见 |

> 注意：历史消息中刚完成方案确认，本轮直接道别，此维度填 1 分。

---

#### F2. 礼貌道别/祝福/兜底询问

**评估重点：** 结束语有没有温度？是通用套话还是有个性化关怀？

| 分数 | 标准 |
|---|---|
| **不涉及** | 本轮不是结束语 |
| **2分** | 针对用户进线情景做了个性化关怀（如发票场景 → "祝顺利开票"；医疗场景 → "祝早日康复"）|
| **1分** | 通用礼貌结束语（"祝您生活愉快""再见"），正确但无特异性 |
| **0分** | 没有任何道别或祝福 |

**✅ 2分示例（个性化）：**
> 场景：用户孩子生病买药送达时间有问题
> 话术：「孩子这边您就费心，遵医嘱优先治疗，也祝咱们早日康复，后续有问题也随时联系。还有其他需要处理的吗？」

**⚠️ 1分示例（通用套话）：**
> 话术：「好的，祝您生活愉快，再见。」

### G. empathy（共情）

> **何时涉及：** 用户在历史消息中或当前轮有明显负面情绪（不满、抱怨、指责、辱骂等）
> **无情绪信号时：** 此维度填"不涉及"

#### 情绪等级判断（打分前先判断）

| 等级 | 定义 |
|---|---|
| **低** | 有不满但克制，仍在聚焦解决问题 |
| **中** | 明确表达不满，有指责倾向，要求被理解 |
| **高** | 情绪宣泄为主，不再关注解决问题，可能有辱骂 |

---

#### G1. 共情质量

| 分数 | 适用情景 | 标准 |
|---|---|---|
| **不涉及** | 本轮用户无负面情绪 | — |
| **2分** | 高浓度情绪 | 以降温为首要目标，充分包容情绪，缓和后再引导到问题核心 |
| **0分** | 高浓度情绪 | 对用户不满进行辩解/反驳，或未共情直接给方案 |
| **2分** | 中浓度 × 初始状态负面 | 提炼用户的核心情绪/诉求"抛回"给用户，让用户感到被理解 |
| **1分** | 中浓度 × 初始状态负面 | 只说"消消气""理解您的着急"，没有基于实际情景主动探寻 |
| **0分** | 中浓度 × 初始状态负面 | 没有情绪安抚，一味追问用户 |
| **2分** | 中浓度 × 负向消费体验/不认可方案 | 正面承接情绪，诚恳致歉，承认服务局限，给出针对性方案或引导接受 |
| **1分** | 中浓度 × 负向消费体验/不认可方案 | 模板式安抚，套话，关怀浮于表面 |
| **0分** | 中浓度 × 负向消费体验/不认可方案 | 没有看到用户情绪，只顾推进流程 |
| **2分** | 中浓度 × 投诉诉求 | 支持用户投诉，承认问题严重性，承诺严肃跟进 |
| **1分** | 中浓度 × 投诉诉求 | 只是接收并处理，没有肯定用户"投诉价值" |
| **0分** | 中浓度 × 投诉诉求 | 展现不屑态度，或侧面反驳用户观点 |
| **2分** | 低浓度 × 不信任渠道 | 用专业自信的语言展示有能力解决，建立信任 |
| **0分** | 低浓度 × 不信任渠道 | 直接转人工，或忽略用户不满继续处理 |

**✅ 2分示例（高浓度情绪）：**
> 用户（历史）：大骂客服，说"你们这个破平台根本不负责"
> 话术：「真的十分理解您为什么会生气和不满，每天起早贪黑出来却接不到单，换谁都得着急。这事是我们没处理好，让您受委屈了。（待用户情绪缓和后）现在最有效的办法就是……」
> 解析：先完全包容情绪，不急着给方案，等用户降温后再引导。

**✅ 2分示例（中浓度 × 负向体验）：**
> 用户（历史）：抱怨餐品有问题，说退款申请被拒太气人
> 话术：「餐品遇到问题，确实很影响心情，如果能退款客服肯定是会帮您去申请的。但这次实在超过处理时效了，我也是很遗憾没能帮到您。」
> 解析：承接了用户情绪（"确实影响心情"），诚恳说明了为什么无法退款（"遗憾"），没有冷漠推脱。

**⚠️ 1分示例（中浓度，套话安抚）：**
> 话术：「理解您的心情，请消消气，我帮您看看怎么处理。」
> 解析：安抚是有的，但很模板，没有看到这个用户具体在生什么气。

**❌ 0分示例（辩解反驳）：**
> 话术：「您好，我们平台的规定是……骑手已经按照要求操作了，这个不属于我们的责任范围。」
> 解析：用规定对抗用户情绪，用户只会更生气。

## 四、禁用话术检查

以下套话出现在话术中，**对所在维度的得分下调1分（最低0分）**：

| 禁用话术 | 说明 |
|---|---|
| "非常感谢您对我们平台的支持" | 空洞套话 |
| "非常感谢您的耐心等待"（用户明显不耐烦/情绪激动时）| 对情绪中的用户说这句会激化矛盾 |
| "您好！感谢您联系XX客服" | 对话已开始后出现此类开场白 |
| "请问有什么可以帮您的" / "有什么可以帮到您" | 任何时候均禁止，含对P3信息缺失型的追问场景 |

## 五、完整标注示例

### 示例数据

**历史消息：**
```
用户：我这个订单能开发票吗
客服：您好，发票这边是由商家负责开具的，建议您直接联系商家沟通，说明开票需求，这样处理起来会比较快。
用户：我不想自己联系，能不能让平台帮我联系一下
用户：我不知道怎么联系商家，麻烦你们帮我问一下
客服：好的，我现在帮您联系商家沟通开票问题，辛苦您稍等1-3分钟。
客服：感谢您的等待，刚联系到商家了，商家反馈已经和您沟通过开票的事，您可以直接联系商家提供开票信息，由他们来帮您开具。
用户：商家没有联系我啊，我没收到任何消息
用户：这个应该是平台的事情吧，为什么要我自己去联系
客服：理解您的感受，这边我们已经帮您和商家沟通确认过了，商家那边表示已经和您取得联系。发票是由商家开具的，您直接联系商家提供开票信息，反而是最快的方式，不用多等。
用户：好吧，那我知道了
客服：好的，如果联系商家过程中有什么问题，随时可以找我。还有其他需要帮您处理的吗？
用户：没有了，谢谢
```

**话术回复（待评估）：**
```
好的，有需要随时来找我，祝您生活愉快。
```

---

### 标注过程

**第一步：识别动作标签**

- 这轮话术是对话的最后一轮，用户说"没有了谢谢"，客服做收尾
- 动作标签：`closing`
- 用户全程无明显负面情绪（有轻微不满但已化解），`empathy` 不涉及

**第二步：逐维度打分**

**F1. 服务结论确认**
- 话术："好的，有需要随时来找我"
- "好的"承接了上文"没有了谢谢"，算是对本次服务的语义收尾
- → **1分**

**F2. 礼貌道别/祝福/兜底询问**
- 话术："祝您生活愉快"
- 本次服务是发票咨询，是否得到圆满解决存疑（商家和用户是否真的沟通了还不确定），客服用了通用结束语
- 没有针对"发票问题"做个性化关怀（如"希望开票顺利"）
- → **1分**（通用套话，无特异性）

**其他维度：** 均填"不涉及"（本轮不含厘清/外呼/询问/凭证/方案/共情内容）

**禁用话术检查：** 无禁用话术

## 六、常见疑问

**Q：历史消息中客服已经说了某件事，本轮还要评吗？**
A：如果本轮话术没有涉及该内容，填"不涉及"即可，不扣分。标注的是**当前轮**的表现。

**Q：一轮话术命中了多个动作标签，怎么处理？**
A：对每个命中标签的对应维度分别打分，互不影响。

**Q：我觉得某条示例判断有争议，怎么办？**
A：有争议的 case 请在备注栏注明，汇总后由负责人集中裁定，形成新的示例。

**Q：情绪等级怎么判断，中/低很难区分？**
A：关键看用户的沟通目的是否发生了转变。低浓度：还在聚焦问题、只是顺带表达不满。中浓度：开始要求"你们应该…"，情绪本身成为了沟通的一部分。

**Q：某些维度我完全拿不准，怎么办？**
A：优先参考示例，如仍拿不准，在备注栏标注"存疑"，不要瞎填一个分数。
