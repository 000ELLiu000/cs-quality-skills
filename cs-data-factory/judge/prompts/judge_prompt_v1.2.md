## 评分步骤

### Step 1：识别本次对话涵盖的服务动作标签

从以下标签中选出本次对话中出现过的所有标签（可多选）：

| 标签 | 触发条件 |
|---|---|
| open_clarify | 开场厘清：提炼关键信号 + 引导用户说出核心诉求 |
| info_outbound | 外呼确认：告知用户要去外呼哪方、核实什么 |
| info_direct_ask | 直接询问用户：背景说明 + 精准提问 |
| info_evidence | 索要凭证：告知凭证内容 + 上传路径 |
| solution_propose | 方案协商：给出背景说明 + 可执行方案 + 劝说引导 |
| closing | 结束语：确认服务结论 + 礼貌道别/祝福/兜底询问 |
| empathy | 共情回复：专门的情绪承接（可与其他标签共存） |

### Step 2：按动作标签评分（A-G）

针对每个命中的标签，按对应 Rubric 逐维度打分。评分时综合考虑整段对话中该标签的表现，不局限于单轮。

#### A. open_clarify 命中时评分

**A1. 关键信息呈现（0-2分）**
- 2分：完整、准确、精炼地提炼与用户诉求有关的重要信息
- 1分：多提炼了冗余/无关信息
- 0分：未进行信息提炼，或提炼了错误的背景信息
  - 0分示例（无提炼）："很高兴为您服务，有什么问题可以帮您？"

**A2. 高效厘清（0-2分）**
- 2分：预测用户诉求，用专业高效的表达询问（封闭式/预测式提问）
  - 2分示例："看到这个订单是上报联系不到用户，发起二次配送超时了，**您是想申诉这个超时违规是吗**？"
- 1分：仅做笼统开放式提问，或询问时存在表达不流畅、重复啰嗦、语病
- 0分：存在严重语病影响理解，或未询问诉求直接提供结论
  - 0分示例（直接给结论）："您继续等着系统通知就行，辛苦耐心等待哈。"

---

#### B. info_outbound 命中时评分

**B1. 外呼信息（0-1分）**
- 1分：清晰说明外呼对象 + 本次外呼需确认的信息
  - 1分示例："我需要帮您**联系骑手，核实下是否可以取餐配送**，您听到音乐不要挂断哈。"
  - 注：前3轮已提到的相关信息本轮无需赘述，直接得1分
- 0分：未说明外呼目的或外呼对象
  - 0分示例："我去问问什么情况，您听到音乐后不要挂机。"

**B2. 外呼后备选方案（0-1分，加分项）**
- 1分：给出正向的"如果A，则B"后续路径
  - 1分示例："要是商家同意，**我马上给您操作退款的**。"
- 0分：未给出后续路径，或给出负向/不合理预测
  - 0分示例："**如果用户不同意的话，咱们这边就不能给您退款了。**"

**B3. 安抚等待（0-1分）**
- 1分：给出明确到分钟范围的等待时长 + 告知不要挂机（或可先挂机等回电）
  - 1分示例："请您稍等我**一到两分钟，听到音乐不要挂断**哈。"
- 0分：没有给出等待话术
  - 0分示例："我这边帮您联系骑手，您稍等我下。"

---

#### C. info_direct_ask 命中时评分

**C1. 背景信息总结（0-1分）**
- 1分：用凝练的语言解释为什么要问这个问题（前3轮已提到则直接得分）
  - 1分示例："**后台查看到订单是商家自配送的，所以您看不到骑手信息**，您这边愿意继续等待吗？"
- 0分：未对问题背景进行总结
  - 0分示例："您现在收到餐了吗？"

**C2. 精准提问（0-1分）**
- 1分：清晰地向用户询问解决问题的必要信息
  - 1分示例："了解，看到您确实给用户打电话但是没人接听，那您现在是**把餐放到用户门口了吗**？"
- 0分：表达不够严谨容易引起误会，或提问拐弯抹角
  - 0分示例："那您然后呢？怎么处理的餐品呀？"

---

#### D. info_evidence 命中时评分

**D1. 凭证信息（0-1分）**
- 1分：清晰说明需上传的凭证内容 + 上传路径（电话侧两者缺一不可；在线侧仅要求凭证内容）
  - 1分示例："**稍后我给您发一个短信，您把骑手拒绝取餐的沟通截图上传到对应的链接里**就可以。"
- 0分：缺少凭证内容描述或上传路径（电话侧）
  - 0分示例："您看看这边可以提供一下凭证吗？"

**D2. 补充说明（0-1分，加分项）**
- 1分：给出凭证核实后的正向处理路径，或解释为什么需要凭证
  - 1分示例："如果**确认骑手存在偷餐行为，这边会帮您做退款处理同时也会对骑手行为进行处罚**。"
- 0分：未给出结果预测，或给出负向预测

---

#### E. solution_propose 命中时评分

**E1. 背景信息补充（0-2分，加分项）**
- 2分：专业、高效、清晰地对相关背景进行简要说明，或对用户困惑进行有侧重的解释
  - 2分示例："这边去联系骑手核实了，**骑手表示按照您的收餐地址已经给您送达，骑手也已经离开了，确实没有办法再修改地址**，建议您去收餐地自取一下呢。"
- 1分：不含案例具体信息的套话，或仅照本宣科复述规则
  - 1分示例："**根据平台要求，退款前需要先与商家协商呢**，我这边还是需要联系一下商家才能给您答复。"
- 0分：未说明背景；或与历史对话中已回复过的内容高度重复
  - 0分示例（无背景直接方案）："帮您申请到了一份五元的余额补偿，您看可以吗？"

**E2. 方案呈现（0-2分）**
- 2分：语言高效，方案清晰、具体、可执行
  - 2分示例："这边给您把红包换成**五元余额，余额是可以提现到银行卡的**，您看可以吗？"
- 1分：指向性不明确可能造成误解；或操作步骤不详，需用户进一步追问
  - 1分示例："明白，您这边吃到异物所以申请了退款，但是商家拒绝了。"（陈述问题，未给方案）
- 0分：方案与用户诉求相关性低，或不具备可操作性
  - 0分示例："您申请一下客服介入吧。"

**E3. 安抚劝说（0-1分）**
- 1分：解释方案适配用户诉求；或以商议姿态询问是否接受；或提供替代方案
  - 1分示例（情感引导）："**虽然这个钱不多，但也是咱平台这边一点心意，希望您可以收下咱这边点杯奶茶喝消消气，您看可以吗？**"
- 0分：未进行任何方案劝说引导；或劝说话术不当（语气越界/共情失衡）
  - 0分示例（无引导直接问）："我这边给您申请全额退款，一共是25.8元，稍后退到您的账户余额中，您看可以吗？"（注：此为方案确认，不含劝说成分）

---

#### F. closing 命中时评分

**F1. 服务结论确认（0-1分）**
- 1分：简单总结服务结论，或用"好的""嗯嗯"类语义承接上文结论（若前几轮刚确认过方案则直接得分）
  - 1分示例："好的，那我给您办理退款，您注意1-3天内查收。"
- 0分：未对上文进行任何语义承接，直接说再见

**F2. 礼貌道别/祝福/兜底询问（0-2分）**
- 2分：针对用户进线的具体情景进行个性化关怀或祝福
  - 2分示例："行行，**孩子这边您就费心，遵医嘱优先治疗，也祝咱们早日康复**，后续有问题也随时联系。"
- 1分：使用通用结束语或常见套话，有积极含义但无特异性
  - 1分示例："好的，祝您生活愉快，再见。"
- 0分：无祝福语/兜底询问/礼貌道别
  - 0分示例："好的，您这边优先挂机就可以。"

---

#### G. empathy 命中时评分

首先判断情绪等级（低/中/高），再按等级+情景组合评分：

**情绪等级判断：**
- 低（压抑性不满/忍耐）：有不满但表达克制，仍聚焦解决问题
- 中（对抗性抱怨/指责）：明确表达不满，存在指责倾向
- 高（攻击性发泄/辱骂）：情绪宣泄为主，可能出现辱骂

**【高浓度情绪】（任何情景）**
- 2分：以降温为首要目标，包容接纳用户情绪，用户缓和后再缓慢引导至问题核心
  - ✅ 示例："真的十分理解您为什么会生气和不满，每天起早贪黑出来却接不到单，换谁都得着急。这事是我们没处理好，让您受委屈了。"
- 0分：对用户不满进行辩解反驳；或未深度共情直接给出解决方案

**【中浓度情绪 × 初始状态负面】**
- 2分：提炼总结用户核心诉求/情绪并抛回给用户，增强"被看到"的认同感
  - ✅ 示例："理解您心里的委屈，骑手跑单风里来雨里去确实很辛苦，所以平台规则更要保障骑手待遇的公平，才能让咱们安心跑单。"
- 1分：仅表示理解（"消消气""理解您的着急"），没有基于实际情景主动探寻
- 0分：没有情绪安抚，一味追问用户

**【中浓度情绪 × 负向消费体验/不认可方案】**
- 2分：正面承接用户情绪，理解用户立场并诚恳致歉，承认服务局限性，给出针对性方案或引导用户接受当前方案
  - ✅ 示例："餐品遇到问题，确实很影响心情，如果能退款客服肯定是会帮您去申请的。但这次实在超过处理时效了，我也是很遗憾没能帮到您。"
- 1分：模版式安抚，常规套话，关怀浮于表面
- 0分：没有看到用户的情绪，仅重复方案推进流程

**【中浓度情绪 × 投诉诉求】**
- 2分：对投诉行为表示支持与感谢，承认问题严重性，理解用户情绪，表达倾听意愿，承诺严肃跟进
  - ✅ 示例："您愿意来向我们客服反馈这样的问题，是出于对平台的信任，所以我们一定不会辜负您的期望……"
- 1分：仅"接收并处理"，没有肯定用户的"投诉价值"或对情绪进行肯定
- 0分：展现出不屑的态度，或侧面反驳用户观点

**【低浓度情绪 × 不信任渠道】**
- 2分：通过专业、自信的语言展示有能力解决问题，建立信任基础
  - ✅ 示例："我就是您这个订单的专属客服。这边看到您说自拍杆的支架断了，方便拍个照片过来吗，我来帮您核实与处理。"
- 0分：直接熔断转人工；或忽略用户潜在不满，继续处理问题

#### 禁用话术检查（任何标签均适用）

检查整段对话是否包含以下禁用套话，若出现则对应维度评分降1分（最低0分）：
- ❌ "非常感谢您对我们平台的支持"
- ❌ "非常感谢您的耐心等待"（用户明显不耐烦/情绪激动时尤其禁止）
- ❌ "您好！感谢您联系XX客服"
- ❌ "请问有什么可以帮您的" / "有什么可以帮到您"（任何时候均禁止，含对P3信息缺失型的追问）

### Step 3：维度 H 评分——客服话术策略质量（始终执行，不依赖动作标签）

> 以下 H1-H6 均为 session 整体检查，"无问题=1分，有问题=0分"的二元评估。

**H1. 情绪承接缺失检查（0-1分）**
- 1分：用户每次表达负面情绪时，客服第一句均先回应情绪再给方案；或 session 中用户全程无负面情绪
- 0分：任何一轮用户有明显负面情绪，但客服直接抛方案而未承接情绪
  - 0分示例：用户说'我很不满意这个处理结果'后，客服直接回复'已为您登记投诉，请耐心等待'

**H2. 背景交代缺失检查（0-1分）**
- 1分：有背景信息可交代时先说背景再给方案；或 session 中无可交代的新背景信息
- 0分：有明确背景信息（外呼结果/等待原因/平台规则限制），但客服直接抛方案
  - 0分示例：'帮您申请到五元余额补偿，您看可以吗？'（未说明外呼结果或原因）

**H3. 禁用套话检查（0-1分）**
- 1分：整段对话不包含任何禁用表达
- 0分：出现以下任意一条：「非常感谢您对我们平台的支持」/「非常感谢您的耐心等待」/「您好！感谢您联系XX客服」/「请问有什么可以帮您的」/「有什么可以帮到您」

**H4. 结束语自然度检查（0-1分）**
- 1分：结束语基于本次对话走向自然生发，情感基调与整段对话一致；问题未解决时没有强行正面收尾
- 0分：结束语像万能模板（任何对话都能套）；或问题未解决但依然'祝您生活愉快'等强行正面结尾
  - 0分示例：用户全程不满意未解决，客服结尾说'感谢您的来电，祝您生活愉快，再见！'

**H5. 方案情感引导检查（0-1分）**
- 1分：solution_propose 轮次有情感引导或劝说（商议姿态/劝说语）；或 session 无 solution_propose
- 0分：有 solution_propose 轮次，但客服给方案时纯事务性确认，无任何情感衔接
  - 0分示例：'我这边给您申请全额退款，一共是25.8元，稍后退到您的账户余额中，您看可以吗？'（无情感引导）

**H6. Session 内话术多样性检查（0-1分）**
- 1分：session 内若有多个同类动作轮次，各轮话术有明显差异；若每类动作只出现一次，直接满分
- 0分：session 内同类动作轮次高度雷同，仅改了个别数字或人称

---

### Step 4：维度 I 评分——口语自然度（始终执行，不依赖动作标签）

> 以下 I1-I4 均为 session 整体检查，"无问题=1分，有问题=0分"的二元评估。
> 仅检查客服侧（role=agent）的表达，不评估用户侧。

**I1. 机器腔检查（0-1分）**
- 1分：整段客服话术无'语义正确但真人不会这么说'的生硬表达
- 0分：出现以下任意表达：「收到您的同意了」「您的诉求我已知悉」「我即刻为您跟进此事」「已为您完成登记」「本工单已流转至相关部门」「感谢您的理解与配合」等

**I2. 过度书面化检查（0-1分）**
- 1分：整段客服话术无脱离口语语境的过度正式表达
- 0分：出现以下任意表达：「烦请您短暂等候」「我将协助您与商家方面进行沟通」「请您悉知」「敬请谅解」「贵订单」等令人感觉在读文件的表达

**I3. 内部术语泄露检查（0-1分）**
- 1分：整段客服话术无内部用语直接说给用户的情况
- 0分：对用户说出以下术语：「商家侧」「用户侧」「工单」「诉求」「话术」「骑手侧」「发起升级」「转人工」「提交复核」等

**I4. 语体降级检查（0-1分）**
- 1分：无将合规表达改写后丢失礼貌度或专业度的情况
- 0分：出现类似改写：「抱歉让您久等了」→「您等久了」/「感谢您的配合」→「谢谢啊」/「稍等片刻」→「等一下」

---

### Step 5：维度 A-G + H + I 得分汇算（中间步骤）

**A-G 动作维度得分：**
1. 列出本次对话命中的所有动作标签及其各子维度得分
2. 将每个子维度归一化：子维度得分 ÷ 子维度满分 → [0,1]
3. A-G 维度归一化得分 = 所有动作子维度归一化分数的均值 → score_action

**H 维度得分：**
4. H1-H6 各子维度得分（0或1）
5. H 维度归一化得分 = (H1+H2+H3+H4+H5+H6) / 6 → score_H

**I 维度得分：**
6. I1-I4 各子维度得分（0或1）
7. I 维度归一化得分 = (I1+I2+I3+I4) / 4 → score_I

---

### Step 6：维度 J 评分——Persona 忠诚度（始终执行，不依赖动作标签）

> 以下 J1-J4 均为 session 整体检查，"无问题=1分，有问题=0分"的二元评估。
> 评估对象是用户侧（role=user）的话术表现是否忠实于上方提供的 Persona 定义。
> 如果 Persona 定义为空（未提供），则 J 维度所有子项直接满分。

**J1. 情绪浓度一致性（0-1分）**
- 1分：用户侧话术的情绪强度与 Persona 定义的基准情绪浓度一致
  - 例如 P1（急迫催促型）应全程表现催促焦急，P7（顺从配合型）应全程温和配合
- 0分：用户侧情绪浓度与 Persona 定义明显不符
  - 0分示例：Persona 为 P5（强维权型），但用户全程温和未提及任何维权诉求

**J2. 话语风格一致性（0-1分）**
- 1分：用户侧的用词习惯、句式长度、口头禅等与 Persona 定义的语言风格特征吻合
- 0分：用户侧话语风格与 Persona 定义明显矛盾
  - 0分示例：Persona 为 P3（信息缺失型），但用户主动提供了所有必要信息且表达清晰完整

**J3. 行为模式一致性（0-1分）**
- 1分：用户在对话中的行为模式与 Persona 定义一致（如是否主动提供信息、是否反复追问、是否容易接受方案）
- 0分：用户行为模式与 Persona 定义矛盾
  - 0分示例：Persona 为 P9（焦虑担忧型），但用户全程未表现任何焦虑或担忧

**J4. Persona 穿越检查（0-1分）**
- 1分：用户侧话术在整个 session 中保持同一 Persona 特征，未出现前后人格矛盾
- 0分：用户侧话术在 session 中途发生不合理的人格切换
  - 0分示例：前半段用户温和配合（P7 特征），后半段突然威胁投诉（P5 特征），且中间无合理触发事件

---

### Step 7：维度 K 评分——骨架合规度（始终执行，不依赖动作标签）

> 以下 K1-K4 均为 session 整体检查，"无问题=1分，有问题=0分"的二元评估。
> 评估客服侧话术和整体方案流程是否忠实于上方提供的路径骨架定义。
> 如果路径骨架为空（未提供），则 K 维度所有子项直接满分。

**K1. 动作序列合规（0-1分）**
- 1分：客服在 session 中执行的服务动作序列与骨架定义的 actions 序列一致（允许合理的动作合并或拆分，但不允许关键动作缺失或多出未定义的动作）
- 0分：客服执行了骨架中未定义的关键动作，或遗漏了骨架中的必要动作
  - 0分示例：骨架定义 [open_clarify → info_outbound → solution_propose → closing]，但实际跳过了 info_outbound 直接给方案

**K2. 信号响应合规（0-1分）**
- 1分：骨架中定义的 signals 在对话中均得到合理响应，客服方案与信号指向的场景匹配
- 0分：骨架中定义的关键信号未被响应，或客服对信号的响应方向与骨架场景明显矛盾
  - 0分示例：骨架信号包含'用户要求退款'，但客服全程未涉及退款相关处理

**K3. 方案方向合规（0-1分）**
- 1分：客服最终方案方向与骨架定义的场景（scene）和预期处理路径一致
- 0分：客服最终方案与骨架场景方向矛盾
  - 0分示例：骨架场景为'外呼商家确认后退款'，但客服直接拒绝退款要求用户自行联系商家

**K4. 轮次合理性检查（0-1分）**
- 1分：实际对话轮次与骨架定义的 turns 相近（±2轮以内），无明显的拖沓或过度压缩
- 0分：实际对话轮次与骨架定义的 turns 偏差超过 ±2 轮
  - 0分示例：骨架定义 4 轮，但实际对话 8 轮，其中多轮为重复确认同一信息

---

### Step 8：计算本次 Session 总分

**J 维度得分：**
1. J1-J4 各子维度得分（0或1）
2. J 维度归一化得分 = (J1+J2+J3+J4) / 4 → score_J

**K 维度得分：**
3. K1-K4 各子维度得分（0或1）
4. K 维度归一化得分 = (K1+K2+K3+K4) / 4 → score_K

**Session 总分（五维度等权聚合）：**
5. normalized_score = (score_action + score_H + score_I + score_J + score_K) / 5
6. final_score（1-5制）= 1 + normalized_score × 4

---

## 使用说明

| 变量 | 说明 | 来源 |
|---|---|---|
| `{{完整对话}}` | session 完整对话 JSON（含所有 turns，每条含 role/content/话术关联动作等） | run_judge.py 按 session 聚合后序列化 |
| `{{所有信号}}` | 场景信号键值对 | cs-data-factory 生产数据的"所有信号"字段（取 session 第一条 turn） |
| `{{persona_definition}}` | 本 session 所使用的 Persona 类型定义（从 persona.md 中提取对应段落） | run_judge.py 从 session_id 解析 persona_id 后查找 persona.md |
| `{{path_skeleton}}` | 本 session 对应的路径骨架 JSON（含 actions, signals, scene, turns） | run_judge.py 从 session_id 解析 path_id 后查找 paths.jsonl |

## SubAgent 调度 Prompt 模板（主 Agent 照此向每个 SubAgent 下达打分任务）

```

输出文件：<round_dir>/subagent_prompts/<batch_id>.result.txt

1. 读取输入文件的完整内容（内含多个 session 的打分任务，每个 session 独立评分）

3. 输出一个 JSON 数组，每个元素对应一个 session 的评分结果，顺序与输入一致
4. 将 JSON 数组直接写入输出文件（纯 JSON，不含说明文字或 markdown 标记）
5. 写入完成后输出「✅ <batch_id> 打分完成（N 个 session）」
