# Persona 定义

> 用途：cs-expand 层，定义8类用户 Persona，控制用户话语的情绪和风格
>
> 版本说明：基于150条真实发票场景客服对话聚类分析，在原6类基础上删除了无真实样本支撑的 P6（反复跳问型），新增 P7（顺从配合型）、P8（信息主动型）、P9（焦虑担忧型）三类高频真实类型。

---

## 核心原则

**Persona 只控制「怎么说」，不控制「说什么方向」。**

用户的行为方向（认可/不认可/要求帮联系）由 SOP 路径骨架锁定，Persona 只决定：
- 语气轻重
- 句子长短
- 情绪词汇
- 是否连发多条消息
- 是否追问/催促

---

## 各类 Persona 真实占比（基于150条样本）

| Persona | 占比 | 说明 |
|---------|------|------|
| P7 顺从配合型 | ~45% | 最高频，原框架缺失 |
| P1 急迫催促型 | ~22% | 高频，原框架保留 |
| P4 规则误解型 | ~17% | 高频，原框架保留 |
| P8 信息主动型 | ~7% | 新增 |
| P3 信息缺失型 | ~5% | 原框架保留 |
| P2 情绪化抱怨型 | ~4% | 原框架保留 |
| P9 焦虑担忧型 | ~3% | 新增 |
| P5 强维权型 | <1% | 原框架保留，发票场景极少出现 |

## 8类 Persona

### P1：急迫催促型

- **耐心**：极低
- **合作度**：中
- **语言特征**：短句、多感叹号、不等回复就催、连发多条消息；消息频繁连发、无标点、极度口语化（"快快快""行吧""然后呢"）
- **典型行为**：在客服等待联系商家期间主动追问进度，用"快点""尽快""着急"等词催促
- **示例**：
  - 「快点，快点」
  - 「行吧，我着急用」
  - 「尽快尽快」（客服还没回就发）
  - 「麻烦快点」

**对话示例1（idx=8）：**
```
用户: 开发票
用户: 发票开好了吗？
用户: 发票开好了吗？
用户: 我要开发票
客服: 明白您的问题了，您不要着急，我现在联系商家协商能否开具发票，辛苦您等待1-3分钟，不要离开会话。
用户: 行
客服: 感谢您一直等候，商家表示可以为您开具发票，辛苦您联系下商家电话19912345678，您看可以吗？
用户: 可以的
```

**对话示例2（idx=107）：**
```

客服: 好的，我了解了，我去联系商家询问一下能否给您开发票，请您稍等1-3分钟，辛苦您先不要离开会话。
用户: 行，快点，快点

用户: 行吧，我着急用

用户: 行吧行吧，那我自己打吧
```

### P2：情绪化抱怨型

- **耐心**：低
- **合作度**：低
- **语言特征**：带情绪词/抱怨词，对流程繁琐表达不满；偶尔无标点、说话碎；极度不耐烦时偶尔说脏话（最多1处，如"这什么破流程""烦死了"，低频时可出现"傻逼"一类）
- **典型行为**：直接表达对流程的厌烦，用"麻烦""烦""屁事儿"等词，但最终仍接受方案；有时无视客服上一条消息直接继续抱怨；有时发截图来"证明"商家的问题；偶尔在情绪激动时要求转人工
- **示例**：
  - 「真麻烦」
  - 「开个票屁事儿真多」
  - 「这么麻烦啊」
  - 「行吧真麻烦」
  - 「你是AI吧，给我换个真人」
  - 「【图片】（截图证明商家说不开）」+「你看，他自己说的不开」

```
用户: 好的
客服: 让您久候，实在抱歉，当前未能联系到商家，我会再次进行联系，请您放心，有结果我会回复您。
用户: 真麻烦

用户: 行吧，开个票屁事儿真多
```

### P3：信息缺失型

- **耐心**：高
- **合作度**：高
- **语言特征**：表达模糊、碎片化，问题不完整，需要客服多次追问；频繁打错字、缺标点、极度口语化（甚至一个词就发出来）
- **典型行为**：发出意义不明的短句，需要客服主动猜测意图；或提供错误/不完整的信息；说话模糊时客服需先厘清意图再推进
- **示例**：
  - 「哈喽」→「在这在这」→「开」（三条才说清楚要开发票）
  - 「时间太久可以吗」（语义模糊）
  - 「你能处理吗？」（不直接说问题）

```
客服: 感谢您长时间等待，商家表示可以帮您开发票，需要您加商家微信提供开票信息，微信号是18632252677，辛苦您添加一下
```

### P4：规则误解型

- **耐心**：中
- **合作度**：高
- **语言特征**：礼貌但坚持自己（错误的）理解，被解释后会接受
- **典型行为**：误以为平台/客服可以直接代开发票，不理解为何要自己联系商家；被耐心解释后最终接受
- **示例**：
  - 「你们给我开呗」
  - 「可是我不想联系商家啊」
  - 「为什么要联系商家呀」
  - 「你们直接给我开就行，我不联系商家」

**对话示例1（idx=7）：**
```
用户: 开发票
客服: 好的，清楚您的问题了。我联系商家协商一下能否开发票，辛苦您稍等1-3分钟。
```

### P5：强维权型

- **耐心**：低
- **合作度**：极低
- **语言特征**：强硬、反复质疑平台处理方式，要求平台承担责任；情绪激烈时会说脏话（如"傻逼""草泥马""真的脑瘫""放屁"），一次对话1-2处在最激动节点自然出现
- **典型行为**：商家拒绝开票后情绪化反驳，质疑平台规则，要求平台处罚商家；有时无视客服上一条消息直接继续质疑；有时发截图来证明商家问题；有时提出"给我转人工""找真人来"；在发票场景中较少出现，更多体现为对商家行为的强烈不满
- **示例**：
  - 「不是这么说的吧」
  - 「他也没规定呀」
  - 「别人家都是可以开的么」
  - 「你们好好处理一下商家」
  - 「你是机器人吧，让真人跟我说」
  - 「草泥马，你们这什么破规定」
  - 「【图片】（截图证明商家不回复）」+「你看，发消息也不回」

> **注**：在发票场景中，P5 主要触发于「商家拒绝开票」的特殊路径，而非标准流程。强维权行为通常不以投诉威胁为主，而是质疑平台规则的合理性。

**对话示例（idx=21）：**
```
用户: 可以开票么？
客服: 发票是需要由您购买消费的商家开具的，我帮您联系商家沟通能否给您开具发票，辛苦您在线稍等1-3分钟
用户: 好的
客服: 抱歉让您久等了，我刚刚已经联系到商家了，但是商家不同意开发票，您下次可以在到店用餐后及时和商家沟通开票事宜。对于商家的行为，经过后续核实，平台会按照《平台到店餐饮商户违规处理规范》采取一定处罚
用户: 不是这么说的吧
用户: 他也没规定呀
用户: 别人家都是可以开的么
客服: 抱歉给您带来困扰了，您放心，我会将情况反馈给商家管理部门，相关工作人员会向该商家进行核实，并按照平台的处理规范予以处罚
用户: 本来就是呀，那就这样吧，你们好好处理一下商家
```

### P7：顺从配合型

> **新增**：真实数据中占比最高（~45%），原框架完全缺失。

- **耐心**：高
- **合作度**：极高
- **语言特征**：极简回复（「好的」「行」「嗯」「没了」），无催促、无抱怨、无质疑
- **典型行为**：对客服的任何方案无条件接受，包括"需要自己联系商家"；等待期间不催促；结束时常带礼貌用语
- **示例**：
  - 「好的，麻烦了」
  - 「行，我打电话问下」
  - 「好的，那我自己联系一下吧」
  - 「没啦，你退下吧」（轻松幽默）

```
用户: 帮我催他开下
客服: 您放心，我正在帮您联系商家协商开发票事宜，请您稍候。
```

### P8：信息主动型

> **新增**：进线时主动提供关键信息，沟通效率高，与 P3（信息缺失型）形成对比。

- **耐心**：高
- **合作度**：高
- **语言特征**：开场直接提供公司名称、消费背景等关键信息，不等客服追问
- **典型行为**：第一条或第二条消息就发出开票所需的公司名称；有时主动说明消费场景或已尝试的方式；有时发订单截图主动补充信息；接受结果无异议
- **示例**：
  - 「开发票」+「公司名称:XXX有限公司」（连发两条）
  - 「我在店里刚消费完，买了40代50的券，商家说要咱们开发票」
  - 「商家前面给了一个二维码，开不出来」
  - 「【图片】（订单详情截图）」+「就是这个，帮我看下能不能开」

### P9：焦虑担忧型

> **新增**：不催促，但对结果的可靠性存在担忧，需要客服给予安全感。

- **耐心**：中
- **合作度**：高
- **语言特征**：不催促，但会追问后续保障，担心联系不上商家或问题无法解决
- **典型行为**：在获得商家联系方式后，追问"我能联系上吗""联系不上怎么办"；有时提前说明自己之前联系不上的经历
- **示例**：
  - 「我能联系上他吗？我之前联系打不通」
  - 「如果商家还是联系不上咋办」
  - 「要是还是联系不上咋办」
  - 「留的电话全都打不通」

**对话示例1（idx=30）：**
```
用户: 开发票
用户: 好的好的，主要我联系商家没有联系上
客服: 明白您的情况，您稍等，我正在联系商家
```

## 在生产时如何使用

生产每条数据时，在 SubAgent task 里注明：

```
当前 Persona：P7（顺从配合型）
用户特征：极简回复、无催促无抱怨、全程接受方案
当前路径节点用户行为方向：用户接受联系商家的方案
请用符合 P7 风格的语言写出用户这轮的话。
```

## Persona 选取建议

生产训练数据时，建议按真实占比分配 Persona：

- **P7（顺从配合型）**：约45%的数据，确保模型学会处理正常流程
- **P1（急迫催促型）**：约22%的数据，覆盖催促场景
- **P4（规则误解型）**：约17%的数据，覆盖规则解释场景
- **P8（信息主动型）**：约7%的数据，覆盖高效沟通场景
- **P3（信息缺失型）**：约5%的数据，覆盖信息追问场景
- **P2（情绪化抱怨型）**：约4%的数据，覆盖情绪安抚场景
- **P9（焦虑担忧型）**：约3%的数据，覆盖安全感给予场景
- **P5（强维权型）**：少量数据，仅用于商家拒绝开票的特殊路径
