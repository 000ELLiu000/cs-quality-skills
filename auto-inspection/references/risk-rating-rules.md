# 风险评级规则与输出 Schema

## 综合评级逻辑

三层检查各自独立评定风险等级，最终取三层的最高风险等级。

- 最终风险等级 = max(第一层 3C 风险, 第二层 通用维度风险, 第三层 动态 Rubric 风险)
- 若某层不适用（如 3C 未启用），该层风险等级视为"无"

---

## 第一层：3C 检查评级规则

> 本层仅当 `task_type` 为"数据生产"或"数据修复"时启用，其余任务类型本层不适用，风险等级视为"无"。

3C 检查独立评定风险等级：

| 3C 结果 | 风险等级 |
|---------|----------|
| 出现红牌或黄牌 | 高 |
| 仅出现蓝牌 | 低 |
| 无违规 | 无 |
| 不适用 | 无 |

---

## 第二层：通用质检维度评级规则

通用质检维度基于各维度通过率独立评定风险等级。四个维度分别计算，取该层最高风险等级。

### 维度与通过率阈值

| 维度 | 要求通过率 | 权重 |
|------|-----------|------|
| 准确性 | ≥ 90% | 高 |
| 遵循性/忠诚度 | ≥ 90% | 高 |
| 完整性 | = 100% | 中 |
| 格式合规性 | = 100% | 低 |

### 各维度风险等级判定

**高权重维度（准确性、遵循性/忠诚度）**

| 通过率 | 风险等级 |
|--------|----------|
| ≥ 90% | 无 |
| ≥ 80% 且 < 90% | 中 |
| < 80% | 高 |

**中权重维度（完整性）**

| 通过率 | 风险等级 |
|--------|----------|
| = 100% | 无 |
| ≥ 95% 且 < 100% | 低 |
| < 95% | 中 |

**低权重维度（格式合规性）**

| 通过率 | 风险等级 |
|--------|----------|
| = 100% | 无 |
| ≥ 90% 且 < 100% | 低 |
| < 90% | 中 |

### 通用维度层最终风险等级

取四个维度中风险等级最高的作为第二层风险等级。

---

## 第三层：动态 Rubric 评级规则

动态 Rubric 基于问题率独立评定风险等级。

问题率 = 至少一个 Rubric 维度不通过的样本数 / 样本总数

| 问题率 | 风险等级 |
|--------|----------|
| ≥ 30% | 高 |
| ≥ 10% 且 < 30% | 中 |
| > 0 且 < 10% | 低 |
| 0%（全部通过） | 无 |

> 权重（高/中/低）是 Rubric 维度的属性，用于标注该维度的重要程度，不参与风险等级的计算。风险等级只看问题率即不通过样本的比例。

---

## 最终风险等级与处置建议

取三层中风险等级最高的作为最终风险等级。

| 最终风险等级 | 含义 |
|-------------|------|
| 高 | 整批质量不可接受 |
| 中 | 部分样本有问题，需定位修正 |
| 低 | 个别问题，可逐个处理 |
| 无 | 质量合格 |

---

## human_attention_items 生成规则

以下情况需要生成人工关注事项：

| 情况 | 优先级 |
|------|--------|
| 发现可能反映 Skill 系统性缺陷的模式（多样本同类问题） | 高 |
| 标签 / 元数据与内容不一致，可能影响下游使用 | 高 |
| 边界 case 无法确信判断，需人工裁定 | 中 |
| 问题可能涉及 Skill prompt 逻辑缺陷，建议排查 | 中 |

---
